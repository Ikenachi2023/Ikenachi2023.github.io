GitHubチートシート

ブランチの作成からPRのマージまでの流れをまとめる。すべての操作はVS Codeのソース管理機能を使う前提で解説する。

1

ブランチを切る

意味と必要性

§

ブランチ = mainから作業用のコピーを1本切り出すこと。mainを直接汚さずに、自分の作業スペースの中で自由に変更・実験ができる。失敗してもmainには一切影響しない。うまくいった変更だけを、あとでPRを使ってmainに反映すればいい。

VS Code上での操作

  1. ブランチを切る前に、まずmainを最新化する。ステータスバーがmainになっていることを確認し、...メニュー(またはソース管理パネル)から「フェッチ」→「プル」を実行して、リモートの最新変更を取り込む。ステータスバーに「同期の変更」(⟲アイコン)ボタンが出ている場合は、それをクリックするだけでフェッチとプルをまとめて行える。
  2. 画面左下のステータスバーに表示されているブランチ名をクリックする。
  3. 画面上部に候補一覧が出るので+ 新しいブランチの作成...を選ぶ。
  4. ブランチ名(例：ikeda/fix-header-layout)を入力してEnter。自動的にそのブランチへ切り替わる。
なぜ先にフェッチ/プルするのか：古いmainからブランチを切ると、他の人の変更が反映されておらず、あとでコンフリクトが起きやすくなる。ブランチを切る直前に同期しておくことで、常に最新のmainから作業を始められる。
ブランチ名のルール：[gitのユーザー名]/[ハイフン区切りの簡単なタイトル](例：ikeda/add-login-form)
確認方法：ステータスバーの表示がデフォルトのmainから、決めたブランチ名に変わっていればOK。
2

コミット&プッシュ

意味と必要性

◇

コミット = 変更内容を記録すること。プッシュ = その記録をGitHub上のクラウドにも反映すること。コミットまではローカルPCの中だけの話で、プッシュして初めてチームの誰からも見える状態になる。

VS Code上での操作

  1. アクティビティバーのソース管理アイコンを開く。
  2. 「変更」欄に編集したファイルが並ぶので、ファイルにカーソルを合わせて+を押しステージングする(まとめてなら「変更」の右の+)。
  3. 上部のメッセージ欄にコミットメッセージを書いてコミットし、そのままプッシュする。
コミットメッセージのルール：Conventional Commit形式。先頭にfix:(バグ修正)、feat:(新機能)、docs:(ドキュメント)等を付ける(例：feat: ログインフォームを追加)。詳細はConventional Commits公式サイトを参照。
3

Pull Request（PR）を作成

意味と必要性

⇄

PR = 自分のブランチの変更を、mainに反映してほしいという申請。いきなりmainに反映せず、一度他の人に変更内容を見てもらうことで、バグの混入を防ぎ、変更の意図をチーム全体で共有できる。

GitHub上での操作

  1. 当該のGitHubリポジトリページを開く。
  2. Compare & pull requestボタンが出ているので押す。
  3. タイトルと説明欄に「何を・なぜ変更したか」を書き、Create pull requestを押す。
4

レビューしてもらう

意味と必要性

◎

合流前に、第三者の目で変更内容をチェックしてもらう工程。自分では気づけない考慮漏れやバグを防ぎ、チーム内で変更の意図を共有する役割もある。

このチームでは：説明で伝えた人がレビューを行います。Reviewersに設定してください。
詳しくは：PR作成画面のテンプレを参考にしてください。

GitHub上での操作

  1. GitHub上のPR画面右側にあるReviewersの歯車アイコンをクリックする。
  2. レビュー担当者をリストから選択してReviewersに設定する。
  3. あとは担当者からの応答(コメント・Request changes・Approve)を待つ。
  4. Request changesが来た場合は、同じブランチで修正してコミット&プッシュすれば、同じPRに自動で追加される。
Tips：LGTM(Look Good To Me)は「いいよ」という意味。承認コメントでよく使われる。
5

マージ

意味と必要性

✓

承認された変更を、mainに正式に取り込むこと。これで自分のブランチの変更がmainに統合され、チーム全員がその変更を使える状態になる。

GitHub上での操作

  1. Approveが揃ったら、PR画面のMerge pull requestを押す。
  2. 続けて表示されるDelete branchを押し、役目を終えたブランチを削除する。

VS Code上での操作

  1. ブランチをmainに切り替えてpullし、最新化する。
